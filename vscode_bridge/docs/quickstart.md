# VSCode 桥接快速开始

这个插件让 N.E.K.O. 通过本地 WebSocket 连接 VSCode 扩展，读取/修改 VSCode 工作区代码，并把结果回到 N.E.K.O. 对话里。

## 0. 确认两端都已启动

**N.E.K.O. 侧**

1. 打开 Plugin Manager。
2. 在插件列表找到 **VSCode 桥接**（id: `vscode_bridge`），启用并启动它。
3. 如果它是通过 **Development** 页面加载的，N.E.K.O. 重启后需要在 Development 页面手动点 **Start**。
4. 打开插件详情里的 **VSCode 桥接** 面板，确认「连接」卡片显示：
   - 服务：运行中
   - 端口：有具体数字
   - 发现文件：有路径

**VSCode 侧**

1. 安装扩展：
   ```bash
   code --install-extension neko-vscode-extension-0.1.3.vsix
   ```
2. 重新加载 VSCode 窗口，打开一个工作区文件夹。
3. 状态栏出现 `N.E.K.O.`。如果显示未连接，运行命令 **N.E.K.O.: 连接** 或 **N.E.K.O.: 检查连接**。
4. 插件面板的「工作区」数量应变为 1。

## 1. 绑定 coding 模型（可选，推荐）

不绑定也能用：默认 `auto` 模式下，主模型会直接调用读文件、搜索、改代码、看诊断等工具。

想让 N.E.K.O. 用单独的 coding 模型跑多步任务：

1. 打开 Plugin Manager → **Plugin API / 模型 API** 页面，添加一个模型槽位：
   - 名称
   - 协议：OpenAI Chat 或 Anthropic Messages
   - 模型 ID
   - API Base URL
   - API Key
   - 能力：至少勾选 `text` 和 `tool_calling`；需要流式可加 `streaming`
2. 保存后点 **测试连接**。
3. 回到 **VSCode 桥接** 插件详情 → **配置** → **模型 API 绑定**。
4. 给 `coding` 用途选择刚才的槽位。
5. 回到插件面板，在「Coding 模型」卡片点 **测试 Coding 模型**。

模型模式说明：

- **自动**：绑定了 coding 模型就用 coding 模型；没绑定就用主模型。
- **专用 Coding 模型**：只用 coding 模型；未绑定时任务会报错。
- **主模型**：只用主模型和细粒度工具。

## 2. 开始使用

直接用 N.E.K.O. 对话，例如：

- 「看一下当前 VSCode 工作区的 README，总结一下」
- 「把 src/App.tsx 里的标题改成 XXX」
- 「帮我给 utils 加一个函数，并补一个测试」
- 「当前文件有什么报错？」

也可以在 VSCode 里运行命令 **N.E.K.O.: 向工作区提问**。

任务流程：

- **主模型模式**：主模型直接调用 `vscode_read_file`、`vscode_search`、`vscode_apply_edits`、`vscode_diagnostics`、`vscode_run_command` 等工具。
- **Coding 模型模式**：主模型调用 `vscode_coding_task`，插件用绑定的 coding 模型跑多步 agent 循环。
- **小改**：通常同步返回结果。
- **长任务**：先返回「已开始」，完成后在 N.E.K.O. 聊天里汇报；面板显示步骤，VSCode 状态栏显示进度。

## 3. Coding 权限与审阅修改

在插件面板 →「模型与权限」里选择三档之一：

- **请求审批**（默认）：修改前始终弹 diff；每条终端命令都确认。
- **自动接受编辑**：代码修改自动应用；安全的测试/构建命令自动执行，风险命令仍会弹窗确认。
- **完全访问**：修改和命令都不再询问；极端危险命令（`rm -rf /`、`mkfs`、`dd if=`、`shutdown` 等）仍会被拦截。

「请求审批」下的修改流程：

1. N.E.K.O. 提议修改后，VSCode 会自动打开 diff。
2. 同时弹出通知，按钮是 **查看 / 应用全部 / 放弃全部**。
3. Explorer 里也会出现 **N.E.K.O. 待应用修改** 树。
4. 也可以用命令：
   - **N.E.K.O.: 查看待应用修改**
   - **N.E.K.O.: 应用全部待应用修改**
   - **N.E.K.O.: 放弃全部待应用修改**
   - **N.E.K.O.: 回滚上次应用的修改**

「自动接受编辑」和「完全访问」会把修改直接写入文件，不再打开 diff；仍可以用 **N.E.K.O.: 回滚上次应用的修改** 恢复。

## 4. 终端命令

- 终端有独立总开关「允许终端命令」，默认开启；关闭后任何权限模式都不会执行命令。
- **请求审批**：每条命令确认。
- **自动接受编辑**：`pytest`、`npm test`、`cargo test`、`go test`、`git status` 等安全命令自动执行；安装依赖、`git push`、`rm`、`curl`、`ssh` 等风险命令弹窗确认。
- **完全访问**：命令不再询问；极端危险命令仍被拦截。
- 所有命令默认不用 shell，cwd 限制在工作区内，有超时和输出上限。

## 5. 长任务与 Coding 接管

- 默认 `max_steps=0`、`task_timeout_seconds=0`：**不限制步数，也不限制任务总时长**。
  - 可在「模型与权限」→「运行预算」调整；0 仍表示不限制。
  - `model_timeout_seconds` 默认 1800 秒，只限制单次模型请求，防止请求挂死。
- 面板顶部有「运行状态」卡：阶段、步数、耗时、当前消息、最近工具；运行中每 1 秒刷新。
- 「运行」页签有完整「运行事件」表：时间、阶段、工具、消息、结果；可随时取消任务。
- 「运行」页签可以直接输入 coding 请求并点 **用 Coding 模型执行**，不依赖主模型是否调用插件。
- 如果 N.E.K.O. 主模型经常不调用工具却声称写了文件：
  - 在「模型与权限」把 **Coding 接管** 设为 **自动**；对明确的 coding 请求，插件会直接启动真实任务。
  - 完成后的实际文件列表会以插件事实气泡显示，不经过主模型改写。
  - 也可以设为「建议」或「关闭」。

## 6. 常见问题

- **面板显示工作区 0**：确认 VSCode 打开了文件夹；扩展已安装并激活；运行 **N.E.K.O.: 检查连接**；查看 VSCode 的 Output Channel **N.E.K.O. 桥接**；确认发现文件路径存在。
- **服务显示运行但扩展一直连接中**：升级到插件 0.1.3；旧版可能在临时 event loop 上创建服务。也可以先在面板点 **停止服务**，再点 **启动服务**。
- **连接失败 / token 不匹配**：在插件面板点 **重新生成 Token**，扩展会自动从发现文件重新读取；也可以在扩展设置里手动填 `neko.bridge.url` 和 `neko.bridge.token`。
- **没有 coding 模型**：面板「Coding 模型」显示 unbound；去配置页绑定，或把模式选为自动/主模型。
- **模型不支持工具调用**：绑定页会标记为不兼容；换一个支持 `tool_calling` 的模型槽位。
- **N.E.K.O. 重启后不连接**：打包安装的插件会按 `auto_start` 自动启动；Development 插件需要在 Development 页面手动 Start。
- **远程 SSH / WSL / Dev Containers**：0.1.0 暂不支持，只支持本地工作区。
- **更新后**：重新导入新的 `.neko-plugin`，重新安装新的 `.vsix`，并重载 VSCode 窗口。
